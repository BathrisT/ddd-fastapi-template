# Образец: как выглядит README задачи

Это не задача, а пример формы — папка нарочно названа с подчёркиванием, чтобы
не путалась с настоящими (`0002 15-06-2026 Гипотезы в целях/`). Копируйте
структуру, а не содержимое.

Ниже — как бы выглядел README, если бы демонстрационная регистрация из шаблона
делалась задачей.

---

## Задача

Завести пользователя по почте и имени, отправить приветствие от языковой модели
фоном.

## Границы

Чего в этой задаче **нет**:

- подтверждения почты — заводим без верификации, флоу подтверждения отдельной
  задачей;
- ролей и прав — пользователь один вид;
- восстановления доступа;
- правок в `kmk-adaptation-bot` — он здесь только эталон для сверки, **режим
  чтения**.

Границы пишутся один раз в начале и дальше не трогаются. Это единственная часть
задачи, которая не устаревает: план изменится завтра, а «сюда не лезем»
останется верным до конца.

## Не пересматривать

Решено на входе, заново не обсуждаем:

- `id: int`, ноль значит «ещё не сохранён» — развилку «вставить или обновить»
  держит репозиторий;
- приветствие идёт фоновой задачей, а не в запросе: обращение к модели дольше
  ответа HTTP;
- событие публикуется после `commit()` — иначе воркер прочитает базу раньше
  записи.

У каждого пункта причина: без неё через месяц это читается как каприз, и его
переоткроют.

---

## Три подпапки

- **`client/`** — итоговое, что можно показать заказчику;
- **`dev/`** — рабочее: план, брейншторм, прикидки. Устаревает быстро, и это
  нормально;
- **`sources/`** — сырьё: записи, транскрибации, макеты. Читается по требованию,
  а не подряд.
