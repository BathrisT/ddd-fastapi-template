# Кэш зелёного прогона и отбор тестов

Два механизма про одно: не делать работу, ответ на которую известен заранее.
Оба переносимые — про любой проект, где проверки идут минутами.

Реализация — `scripts/precommit_cache.py` и `scripts/select_tests.py`, конфиг —
`[tool.precommit_cache]` и `[tool.test_selection]` в `pyproject.toml`.

У них общее правило поведения при незнании, и читаются они одинаково:
**не знаю — делаю больше**. У кэша незнакомый файл обязан попасть в ключ, у
отбора — обязан отменить отбор.

## Кэш: тот же снимок дерева не проверяют дважды

`make precommit` прогоняется подряд два раза почти всегда: сначала руками,
потом хуком `pre-commit` при самом `git commit`, на ровно том же содержимом.
Индексация файлы на диске не меняет — значит второй прогон гарантированно
повторяет первый и не может узнать ничего нового.

**Ключ считается по СОДЕРЖИМОМУ файлов, а не по диффу.** Соблазн взять
`git diff` здесь опасен: он не показывает untracked-файлы. Новый модуль на
триста строк, ещё не добавленный в индекс, не изменил бы отпечаток — и кэш
отдал бы «зелёное» про файл, которого ни mypy, ни pytest в глаза не видели.
Поэтому берутся все файлы, которые git считает частью проекта: отслеживаемые
плюс неотслеживаемые и не игнорируемые.

**Игнорируемое git'ом не учитывается вовсе** — иначе кэш не сработал бы НИ
РАЗУ: `.mypy_cache`, `.ruff_cache`, `.coverage` переписываются самим же
прогоном, и каждый прогон отменял бы предыдущий.

**CRLF приводится к LF.** При `core.autocrlf=true` (Windows по умолчанию)
`git checkout`, `git stash` и `git stash pop` переписывают переносы строк в
рабочем дереве, а git считает файл неизменным. Без нормализации ключ съезжал
бы от операций, ничего не меняющих по смыслу, — а `pre-commit` как раз стэшит
неиндексированное вокруг своего запуска, то есть кэш разваливался бы ровно в
том сценарии, ради которого заведён.

**В ключ входит окружение** — версия питона и список установленных пакетов.
Обновился mypy или ruff — то же дерево законно даёт другой ответ. Список
читается из интерпретатора, а не из `poetry.lock`: `pip install -U mypy` руками
лока не меняет.

**Чего в ключе нет и быть не может:** живости Docker, версии образа postgres,
состояния сети. Против этого работает только срок годности записи (`ttl_hours`).

**Кэшируется исключительно успех.** Красное не запоминается никогда — иначе
после исправления одной строки нечем было бы перепроверить. Отсюда известный
перекос: флакающий тест, однажды позеленевший, застывает зелёным на этом дереве
до первой правки. Знать про это надо, лечится оно не кэшем.

**Дерево, изменившееся ВО ВРЕМЯ прогона, не запоминается**: правка, приехавшая
под руку тестам, проверку не проходила. Исключение одно и названо в конфиге —
файлы, которые прогон правит сам. Такой у нас `.coverage-baseline`: планка
встала ровно на тот процент, который только что показал зелёный прогон, и
перепроверять там нечего. Изменись вместе с ней хоть один посторонний файл — не
запоминается ничего.

**Вывод команды не перехватывается**, код возврата отдаётся наружу как есть:
золотое правило 7 CLAUDE.md тут не нарушается, ни одного конвейера здесь нет.

**Про попадание сообщается ГРОМКО и с датой.** Отчёт «precommit зелёный» без
слов «из кэша» — тот самый выдуманный результат, от которого предостерегает то
же правило; чтобы так сказать, надо не заметить пять строк на экране.

Разделитель в командной строке — `::`, а не привычное `--`: скрипт вызывают
через `poetry run`, а poetry разбирает свою строку сама и `--` из неё вырезает.

## Отбор: гонять только то, до чего изменения дотянулись

Правка одного сценария не может сломать тесты сторожей, а правка сторожа —
интеграционные тесты с базой.

**Отбор не выводит зависимость, а спрашивает объявленную.** Инструменты,
которые её выводят (tach по графу импортов, testmon по исполненным строкам),
измерены на этом репозитории и оба промахиваются мимо связи
`tests/unit/scripts/**` → `scripts/*.py`: сторож запускается ДОЧЕРНИМ
ПРОЦЕССОМ, и ни импорта, ни исполненных строк карта не видит. Проверено на
настоящей поломке: у сторожа отобрали код возврата, его тест падает семью
проверками — testmon выбрал НОЛЬ тестов. Промах такого рода молчалив: «не
выбрал, потому что не задето» и «не выбрал, потому что не увидел» выглядят
одинаково — пустым списком.

Четыре причины прогнать всё, каждая закрывает свой класс невидимых связей:

1. **Файл не из знакомой зоны.** Список зон белый: чего в нём нет, про то
   ничего не известно.
2. **Файл не `.py`.** Данные, шаблоны, конфиги, `.env.example`, `poetry.lock`.
   Тест читает такой файл, но исполненных строк питона в нём нет — никакая
   карта покрытия эту связь не увидит в принципе.
3. **Файл исчез или переименован.** У удалённого кода нет строк, которые
   кто-то мог бы исполнить: «пропала проверка» не выглядит изменением ни для
   одной карты.
4. **Триггер из конфига.** Миграции (схема приезжает через фикстуру сессионного
   скоупа: она исполняется ОДИН раз, в setup первого теста, и остальные про эту
   зависимость не знают) и любой `conftest.py`.

**База отсчёта — не `git diff`, а последнее ЗЕЛЁНОЕ дерево** (`precommit_cache
changed`). После коммита рабочее дерево чистое, и `git diff` сказал бы «ничего
не менялось» про правки, которых никто не проверял; а если зелёный прогон был
три коммита назад — в счёт пойдут изменения всех трёх.

**Отсеянное записывается, и полный прогон это проверяет.** Отбор — правило,
написанное человеком, и однажды оно соврёт; узнать об этом можно ровно одним
способом — сравнить. Каждое решение уходит строкой в
`.make-cache/selection.jsonl`, а `verify` после полного прогона смотрит, не упал
ли отсеянный тест. Упал — правило названо поимённо вместе с диффом, на котором
оно соврало. Полный прогон прошёл — журнал очищается. Прогон НЕ состоялся
(отчёта нет) — журнал сохраняется, и это разные случаи.
